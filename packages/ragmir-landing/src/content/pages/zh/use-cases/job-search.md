好的求职信需要具体：一项成果、一个项目，或上次考核中的一个数字。多年下来，这些证明会散落在旧简历、考核文件和报告之中。Ragmir 把它们集中索引在一处，助手就能挑选与某个职位相符的证据，并标明出处。

## 知识库包含哪些内容

- **你的每一版简历**，格式为 PDF 或 Word，按页或段落引用。
- **雇主提供的年度考核和反馈**，按页引用。
- **你撰写的项目报告、幻灯片和文章**，按页、幻灯片或行引用。
- **过往的求职信和申请笔记**，格式为 Markdown 或 Word。
- **你保存的证书、推荐信和技能清单**。

Ragmir 可以索引 900 多种文件类型， [支持的格式](/docs/supported-formats/)列出了全部类型。扫描件和图片需要可选的本地 OCR。

## 设置文件夹

把文档保存在同一个文件夹中，将其添加为来源，然后建立索引。这需要 Node.js 22.12 或更高版本：

```bash
npm install -D @jcode.labs/ragmir
npx rgr init
npx rgr sources add "career/**"
npx rgr ingest
```

对于扫描文档，请先检查本地 OCR 引擎，然后进行设置：

```bash
npx rgr ocr doctor
npx rgr ocr setup
```

将每份职位描述保存为文本、Markdown 或 PDF 文件放入该文件夹，也可以直接粘贴到聊天中。新增文档后，再次运行 `npx rgr ingest`；它只读取新增和变更的文件。

## 对照职位描述，再带引用地撰写

要求助手只基于你的证据工作。例如：

```prompt
这是一份职位描述。列出其中五项主要要求。对每一项，在我的文档中找到证据并引用页码。告诉我哪些要求我没有对应的证据。

只使用可以引用的论述撰写求职信。在每条论述后附上引用，不要添加我的文档中没有写明的技能、成果或日期。

我的年度考核中哪些提到了团队合作？请引用原文并标注出处。
```

你也可以手动运行同样的搜索：

```bash
npx rgr search "led the migration project results" --compact
```

当文档中没有证据时，Ragmir 不返回任何结果。没有引用片段支撑的要求，是应当如实告知招聘人员的空缺，而不是用来填补的内容。标记为 `weakEvidence` 的片段需要再看一眼。Ragmir 的 MCP 服务器还内置了 `answer` 提示词，会要求每条论述都附上引用。

## 本地模型还是云端助手

职业文件属于私密内容：考核中含有评价，简历中含有你的联系方式。通过 Ollama 使用本地模型是最安全的选择，因为任何内容都不会离开你的电脑。 [本地 RAG 教程](/zh/local-rag/)介绍了设置方法，包括如何关闭 Ollama 的云功能。

云端助手同样可以使用。它接收的是所读取的片段，而不是整个文件夹，此后服务商的政策同样适用。连接云端助手之前，请先在[本地还是云端指南](/zh/local-vs-cloud-rag/)中检查训练、保留期限、地域、访问权限和范围。

## 限制

- 助手负责起草，由你决定。发送求职信之前，请核对每一个被引用的页面。
- Ragmir 不投递申请、不填写表格，也不发送邮件。它不会读取招聘网站。
- 它不提供职业、法律或人力资源方面的建议，也无法判断你是否适合某个职位。
- 求职信的质量取决于你的文档。证据单薄，求职信就会很短。
- OCR 可能会误读扫描件。请将被引用的页面与原件进行比对。
